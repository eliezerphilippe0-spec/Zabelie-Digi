# Rapport de revue — Zabelie — 2026-08-01

**Mode** : CIBLÉ (périmètre récent) + balayage Sécurité complet · **Périmètre** :
branche `claude/api-v1-tool-ready` à `e5d30de` (empilée sur la tête de #55) —
`lib/api/v1/schemas.ts`, ajout de l'anglais, `app/error.tsx` / `app/not-found.tsx`,
fermeture V-17, + toute la surface API et les 50 migrations pour la sécurité ·
**Stack** : Next.js 16.2.10 (App Router) · Supabase/Postgres · Vercel · Zod 4.4.3

---

## Résumé exécutif

La posture de sécurité est **solide et vérifiable** : 47 tables sur 47 portent
une RLS, les 47 fonctions `security definer` sont toutes révoquées, aucun
`.env` n'est suivi par git, aucun `dangerouslySetInnerHTML`, les crons sont
protégés par secret et les routes d'administration contrôlent toutes le rôle.
Ce n'est pas une posture qu'on trouve par accident.

Les trois problèmes les plus urgents ne sont pas des failles : **trois
vulnérabilités npm de sévérité haute** avec correctif disponible, **aucun
en-tête de sécurité HTTP**, et un **débordement de texte sur le premier bloc de
la page d'accueil à 360 px** — la largeur du terrain visé.

Deux constats sont des dettes de conception plutôt que des bogues : les
libellés de catégories de l'ancienne taxonomie sont des **valeurs stockées**
et ne peuvent donc pas être traduits sans découpler clé et affichage ; et le
`fail-open` du limiteur de débit est un choix assumé qui devient discutable à
mesure que la surface API grandit.

## Constats détaillés

### 🟠 Élevés

#### [SEC-01] Trois vulnérabilités npm de sévérité haute, correctif disponible
- **Axe** : Sécurité · **Effort** : S
- **Emplacement** : `package.json` — `npm audit --omit=dev`
- **Constat** : `next` (>=9.3.4-canary.0), `postcss` (<=8.5.17), `sharp`
  (<0.35.0, vulnérabilités héritées de libvips : CVE-2026-33327, CVE-2026-33328,
  CVE-2026-35590, CVE-2026-35591). `fix available via npm audit fix`.
- **Impact** : `sharp` traite les images téléversées par les vendeurs — une
  entrée non fiable atteint donc libvips. C'est le plus exposé des trois.
- **Preuve** : sortie de `npm audit --omit=dev`, dépendances de production seules.
- **Correctif proposé** : `npm audit fix`, puis relancer `npm test` + `build` +
  `e2e`. Vérifier que la montée de `next` ne casse pas la convention `proxy.ts`
  (Next 16 l'a renommée depuis `middleware.ts`).
- ⚠️ Déjà listé dans le corps de la PR #55 comme constat ouvert, non traité.

#### [SEC-02] Aucun en-tête de sécurité HTTP
- **Axe** : Sécurité · **Effort** : S
- **Emplacement** : `next.config.mjs` — le fichier ne contient que
  `reactStrictMode` et `images.remotePatterns`, aucune clé `headers`.
- **Constat** : ni CSP, ni `X-Content-Type-Options`, ni
  `Strict-Transport-Security`, ni protection anti-clickjacking.
- **Impact** : le site est intégrable dans une iframe tierce — un site
  d'hameçonnage peut encadrer `/connexion` et récolter des identifiants sous
  l'apparence de Zabelie. Sur un marché où la confiance se construit encore,
  c'est le risque le plus concret des trois.
- **Preuve** : lecture intégrale de `next.config.mjs` (15 lignes).
- **Correctif proposé** : bloc `headers()` avec au minimum
  `X-Frame-Options: DENY` (ou `frame-ancestors 'none'`),
  `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`. La CSP
  demande plus de soin : Next injecte des scripts en ligne, une CSP mal posée
  casse la page.

#### [RES-01] Le premier bloc chiffré de l'accueil déborde à 360 px
- **Axe** : Responsivité · **Effort** : S
- **Emplacement** : `app/page.tsx:139-141` — les trois tuiles de statistiques.
- **Constat** : « MonCash » s'affiche « MonCa », « Livraison » devient
  « Livrais », « Delivery » devient « Delive ». Dans **les trois langues** :
  ce n'est pas l'anglais qui déborde.
- **Impact** : c'est le premier élément chiffré de la page d'accueil, sur la
  largeur d'un Android d'entrée de gamme — c'est-à-dire l'appareil de la
  majorité du marché visé.
- **Preuve** : captures Chromium à 360×800, comparées entre `fr`, `ht` et `en`.
  Vérifié à l'écran, pas déduit du CSS.
- **Correctif proposé** : la valeur de la tuile est en `text-2xl`+ sur une
  largeur fixe ; permettre le retour à la ligne, ou réduire la taille sous
  `sm:`. Un `truncate` explicite serait pire — il rendrait la coupure
  intentionnelle.

#### [UX-01] La barre de catégories n'est traduite dans aucune langue
- **Axe** : UX · **Effort** : L
- **Emplacement** : `lib/product-categories.ts:9-17` — `PRODUCT_CATEGORIES`.
- **Constat** : « Business · Carrière · Design · Marketing » s'affiche à
  l'identique en kreyòl et en anglais.
- **Impact** : sur une interface qui revendique trois langues, un rayon en
  français au milieu d'une page anglaise dit que la traduction est partielle.
- **Preuve** : captures des trois langues, chaîne identique ; et
  `lib/product-categories.ts:1-8` documente que le catalogue **filtre par
  égalité stricte** sur ces libellés (BL-105).
- **Correctif proposé** : ⚠️ **ce n'est pas un oubli de traduction.** Ces
  chaînes sont des **valeurs stockées** dans `products.category`. Les traduire
  casserait le filtre pour tous les produits existants. Le vrai correctif est
  de découpler la clé stockée du libellé affiché — changement de conception
  avec migration de données, donc arbitrage porteur.
- **Note** : ne concerne que l'ANCIENNE liste fermée. La nouvelle taxonomie
  (`zabelie_categories`, 123 rayons) porte bien `label_en`
  (`0035_categories.sql:61`) et elle est câblée depuis `4b6ab06`.

### 🟡 Moyens

#### [SEC-03] Le limiteur de débit est `fail-open`, et la surface va grandir
- **Axe** : Sécurité · **Effort** : M
- **Emplacement** : `lib/zabelie-rate-limit.ts:12-28` — `if (error) return true`
  et `catch { return true }`.
- **Constat** : si la base est injoignable, toute limite est levée.
- **Impact** : le raisonnement en commentaire est juste pour les routes
  actuelles — « la requête échouera de toute façon deux lignes plus loin sur
  son premier accès base ». Il cesse de l'être pour une route qui ferait un
  appel coûteux AVANT de toucher la base : `app/api/moncash/return/route.ts:33`
  borne précisément l'amplification de deux appels MonCash par requête, et
  c'est cette borne qui saute en cas de panne Postgres.
- **Preuve** : lecture des deux fichiers.
- **Correctif proposé** : conserver `fail-open` par défaut, mais permettre un
  `failClosed: true` pour les routes qui protègent un coût externe. Ne pas
  inverser le défaut globalement — une panne d'infra ne doit pas bloquer les
  ventes.

#### [SEC-04] La couche API v1 n'a encore aucun handler — le contrat n'est pas exercé
- **Axe** : Sécurité · **Effort** : M
- **Emplacement** : `lib/api/v1/schemas.ts` existe ; `app/api/v1/` **n'existe
  pas** (vérifié : `ls` échoue).
- **Constat** : les 28 tests de schéma valident des objets construits à la main.
  Aucune donnée réelle de Postgres n'a encore traversé ces schémas.
- **Impact** : c'est l'état attendu au commit 1/7, mais il faut le dire : la
  garantie « un statut hors énumération fait échouer la réponse » est prouvée
  sur des fixtures, pas sur la base. Le premier handler est le vrai test.
- **Correctif proposé** : au commit 6, faire passer une commande RÉELLE par
  `GetOrderOutput` avant de déclarer l'endpoint fini.

#### [UI-01] `error.tsx` et `not-found.tsx` n'ont jamais été vus dans un navigateur… sauf le 404
- **Axe** : UI · **Effort** : S
- **Emplacement** : `app/error.tsx`, `app/not-found.tsx`
- **Constat** : le 404 a été vu rendu (capture, trois langues). `error.tsx` ne
  l'a **jamais** été : il est couvert par `renderToStaticMarkup`
  (`tests/ecrans-erreur-rendu.test.ts`), ce qui prouve qu'il ne lève pas, pas
  qu'il s'affiche correctement — notamment que `useEffect` bascule bien la
  langue après hydratation.
- **Correctif proposé** : une route de démonstration temporaire qui lève, ou un
  parcours e2e qui force une erreur de rendu.

#### [UX-02] `loading.tsx` absent sur 25 pages
- **Axe** : UX · **Effort** : M
- **Emplacement** : aucun `loading.tsx` dans `app/`
- **Constat** : hors périmètre par décision explicite du 2026-08-01 — il change
  ce que voient les utilisateurs en fonctionnement normal (rendu en flux) et
  demande une vérification visuelle.
- **Impact** : sur 3G, une page dynamique reste blanche jusqu'au premier octet.
- **Correctif proposé** : geste séparé, avec captures avant/après.

### 🔵 Faibles

#### [SEC-05] `commission_rate_bps` est appelable par `anon` via PostgREST
- **Axe** : Sécurité · **Effort** : S
- **Emplacement** : `supabase/migrations/0005_commission.sql:18-24`
- **Constat** : fonction `language sql immutable`, **sans** `security definer`,
  et sans `revoke`. PostgREST expose donc `/rest/v1/rpc/commission_rate_bps`.
- **Impact** : quasi nul — elle renvoie une constante de politique (1000 ou 600
  points de base) que `faq.a3` publie déjà en clair (« la plateforme prélève
  10 % »). Aucune donnée utilisateur.
- **Note d'honnêteté** : mon premier instrument l'avait classée
  `security definer` — c'était un **faux positif**, sa fenêtre de lecture
  débordait sur la fonction suivante. Corrigé et revérifié.
- **Correctif proposé** : `revoke` par cohérence avec les 47 autres, ou décision
  explicite de la laisser publique. Pas urgent.

#### [UI-02] Le sélecteur de langue est passé de 2 à 3 boutons sans revue visuelle mobile
- **Axe** : UI · **Effort** : S
- **Emplacement** : `components/lang-toggle.tsx:61-65`
- **Constat** : les zones tactiles de BL-124 (`px-3 py-2`) sont conservées, mais
  le conteneur s'élargit d'un tiers dans un en-tête déjà dense à 360 px.
- **Preuve** : capture — l'en-tête tient, sur deux lignes (logo + sélecteur +
  « Vendre », puis « Catalogue · Talents »). Lisible, mais serré.
- **Correctif proposé** : aucun si le porteur juge la capture acceptable.

### Provenance — quel arbre a produit quel constat

Le conteneur a été réinitialisé **pendant** la revue : les contrôles menés
avant la détection ont porté sur `70ed8ac`, ceux d'après sur `e5d30de`. Plutôt
que d'estimer l'impact, il a été mesuré fichier par fichier
(`git diff --quiet 70ed8ac e5d30de -- <fichier>`) :

| Artefact audité | État entre les deux arbres | Conséquence sur le constat |
|---|---|---|
| `next.config.mjs` (SEC-02) | **identique** | aucune |
| `vercel.json`, `proxy.ts`, crons | **identiques** | aucune |
| `app/api/moncash/return/route.ts`, `lib/zabelie-rate-limit.ts` (SEC-03) | **identiques** | aucune |
| `lib/product-categories.ts` (UX-01) | **identique** | aucune |
| `package.json` (SEC-01) | modifié — ajout de `zod` **seul** | aucune : `next`/`postcss`/`sharp` inchangés |
| `app/page.tsx` (RES-01) | modifié (75 lignes) | **revérifié** : les lignes 139-141 citées sont identiques sur les deux arbres |
| `components/lang-toggle.tsx` (UI-02) | modifié | constat issu d'une capture prise sur l'arbre courant, pas d'une lecture |
| migrations `0045`→`0048` | modifiées — **en-têtes seuls**, zéro ligne SQL (commit `80df1dd`) | aucune |
| migrations `0049`/`0050` | **absentes** de l'arbre périmé | seule divergence réelle — voir ci-dessous |

**La seule divergence qui portait un constat** : le premier scan
`security definer` signalait `zabelie_handle_new_user()` comme non révoquée.
C'était un artefact de l'arbre périmé — `0049` la révoque. Le scan a été
**rejoué** sur `e5d30de` : 47 fonctions, 0 non révoquée.

**Le scan RLS n'avait PAS été rejoué** au moment de la première rédaction : il
l'a été depuis. `0049` et `0050` ne créent **aucune table** (`grep -c
"create table"` → 0 et 0), donc le décompte ne pouvait pas bouger, mais le
vérifier coûtait moins cher que de le raisonner. Résultat sur l'arbre correct :
**50 migrations · 47 tables · 0 sans RLS.**

**Deux instruments ont menti avant d'être corrigés**, et c'est consigné parce
qu'un instrument non éprouvé ne prouve rien :
1. Le scan RLS a d'abord annoncé **19 tables sans RLS** — son expression
   régulière exigeait une seule espace, or `0002_rls.sql:5-12` aligne les
   colonnes. Après correction et contrôle connu-positif : **47/47 protégées**.
2. Le scan `security definer` a d'abord signalé `commission_rate_bps` — fenêtre
   de lecture débordante. Après resserrement et contrôle dans les deux sens
   (47 fonctions détectées, aucune non révoquée) : **0 constat**.
